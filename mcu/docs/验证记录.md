# 验证范围与记录

本轮验证在离线进行：没有打开真实串口、没有向真实舵机输出PWM、没有ARM实机、没有下载STM32，也没有改动FPGA。Keil编译与假HAL运行均使用本工程当前源码，不把原交接包历史测试当作本轮结果。

## 自动验证

`python tools/check.py` 使用原生GCC `-Wall -Wextra -Werror`，运行真实C接收器、原标定模型、批次控制器、动作核心和OLED字库。PWM与事件回调均为假接口。检查覆盖：

- FPGA UART标准向量、CRC损坏、噪声重同步、重复槽位拒绝、空心跳和类别规则。
- 五点映射、第三/四点后仍不提前完成、五步OLED坐标提示、两个新增点分别参与最小二乘解、旋转/反向像素轴、采样均值、共线/细长点集与非有限值拒绝、冻结源帧不能靠新SEQ完成标定。
- 同一场景四目标、槽位变化、未知数字不抓、目标消失返回空闲、坐标移动重启确认、通信中断不开始新任务。
- 原31个真实cm标定点逐一预测，并对照保留JSON中的CH3～CH6脉宽；非零Z和凸包外拒绝。
- 冻结批次后注入错误坐标/数字、目标丢失和视觉串口故障，冻结位置/标签不改变，仍完成原队列。
- 实际X排序、X相同按Y排序；X<15的偶数仍右放、X≥15的奇数仍左放，证明没有沿用原“按X选左右”的策略。
- 方块3不抓，方块1245不抓并出异常事件；两目标过近、映射越界不启动相应任务。
- 各动作阶段的CH5先后、底座转向、夹爪开闭、最终默认闭爪，已抓位置抑制重复抓。
- SEQ/FRAME16位回绕、重复包拒绝、本地暂停冻结及控制核心恢复逻辑，以及自动模式不依赖电脑心跳。生产固件暂停后通过RESET恢复。
- 五次插值单调、端点一致、CH5/CH6峰值速度与加速度限制；这是指令数学检查，不是实测舵机速度。
- 2026-10-27补充：夹爪运行850/1500与原模型1000/1600分别验证，运行开度越界拒绝；无位移回位段不等待；六关节大小行程及降低板级上限时的峰值速度/加速度约束。
- 2026-10-28连续动作补充：16种左右组合×全抓/中间跳过与阻止/仅一件可抓共48个批次，检查中间只开爪一次、只在最后回默认闭爪、横移期间CH5保持2191μs，以及下落前其他关节到达指令终点。另测抬臂/高位交接/下一目标横移时暂停、无效下一点拒绝、连续策略与任务号冲突、余项意外取消后的最终回位。
- OLED每行不超21字符，同一实际字库生成映射/确认/抓取/完成六张128×64像素预览（含新增第4、5步）。

实际检查计数和时间见`tests/results.json`及`tests/native_results.log`。断言数量包含每次模拟PWM检查，不等同于独立测试场景数。



`python tools/build.py` 使用本机Keil ARMCC5 Rebuild，输出`tests/keil_build.log`、`firmware/build_report.json`和新HEX。脚本检查Intel HEX校验、所有实际Flash地址必须在0x08000000～0x0800FFFF、静态RAM及4KB栈/512B堆总分配不超过20KB。ST-Link配置继承原Debug和Utilities，构建不会触发下载。

`python tools/provenance.py` 对原交接包SHA256SUMS逐文件校验，确认原模型字节一致，记录FPGA主源码/约束摘要，并生成标定参数文档。

`python tools/check_download.py`核对原工程的器件/包、CPU与内存、ST-Link驱动、Utilities、Flash算法、SWD与复位等14组配置，核对六路PWM定时器映射，确认USART1和所有UART TX均未启用。结果见`tests/download_config_check.json`。新Keil可能在Rebuild时自动升级PackID、nTsel等字段，构建脚本结束时恢复为原交接工程配置并再次验证，未调用下载。

## 实物验收仍需完成

当前结果不包含SSD1306实物画面、I²C波形、USART3收包、实际舵机方向/行程、抓取成功率或位置精度实测。首次接入应逐项核对：OLED五点提示与均值、原坐标系的实际五点、映射后独立验证位置、先单目标后多目标、CH5抬降顺序、左右放置与PB12暂停。原模型局部约10cm误差被保留，需要针对该区域补点或复核原标定；本轮不虚构新的空间精度。

无外部反馈时，固件只能按脉宽轨迹和停留时间判断动作段结束，无法检测夹空、舵机堵转、工件中途滑落或实际到位。批次模式按用户要求假定剩余工件静止，抓取期忽略视觉。
