# FPGA 视觉分拣机械臂 · STM32F103C8T6

Keil v5 工程：[`MDK-ARM/RobotArmControl.uvprojx`](MDK-ARM/RobotArmControl.uvprojx)。
构建固件：[`firmware/robot_arm_control.hex`](firmware/robot_arm_control.hex)。下载方式和Debug、Utilities、Flash算法、SWD及复位配置已与原交接工程逐项核对一致。六路PWM引脚完全沿用原接线。FPGA项目和原机械臂交接包未改动。

本工程将原有真实 31 点空间模型、默认/左右放置姿态与 FPGA `SORT UART v1` 接通，完成五点像素映射、四目标稳定确认、整批冻结、分类抓放和单屏 SSD1306 显示。不使用 PID；通过分关节速度/加速度约束的五次平滑 PWM 轨迹运动。PWM 是位置指令，没有位置、速度或夹持反馈。

## 接线

原有/新增功能分列说明见[`docs/引脚配置.md`](docs/引脚配置.md)。

|用途|STM32 引脚|连接|
|---|---|---|
|夹爪 CH1|PA0 / TIM2_CH1|原接线；开 **1000**、闭 **1500μs**（2026-10-28张开恢复）|
|夹爪旋转 CH2|PA1 / TIM2_CH2|原接线，固定 1382μs|
|定位 CH3|PA2 / TIM2_CH3|原接线|
|定位 CH4|PA3 / TIM2_CH4|原接线|
|升降大臂 CH5|PA6 / TIM3_CH1|原接线|
|底座 CH6|PA7 / TIM3_CH2|原接线|
|FPGA 视觉接收|**PB11 / USART3_RX**|FPGA **GPIOA6 / T2 / GPIOA 排针 J1 第7脚** → PB11|
|公共地|GND|FPGA GPIOA 排针 J1 第12或28脚 GND → STM32 GND|
|OLED SCL|**PB6**|四针 SSD1306 SCL|
|OLED SDA|**PB7**|四针 SSD1306 SDA|
|OLED 供电|3.3V、GND|模块 VCC、GND；I²C 上拉至 3.3V，地址 0x3C|
|暂停输入，可选|PB12|拉低到 GND 锁定暂停；不接时内部上拉|
|ST-Link|PA13、PA14、GND|SWDIO、SWCLK、GND；沿用原 SWD 接线|

FPGA 的 GPIOA6 与 STM32 的 PA6 不是一回事：STM32 PA6 已被 CH5 使用，视觉输入必须接 PB11。视觉串口为 115200、8N1、3.3V TTL。
本版本没有STM32电脑串口测试控制或电脑事件发送：PA9、PA10、PB10未使用，不需要连接USB-TTL。PB11只接收FPGA数据，UART发送功能关闭。
舵机沿用独立供电与共地。STM32 的 3.3V 和 OLED 电源不用于给舵机供电。

## 使用流程

1. 打开 Keil 工程，选择 `RobotArm_Vision_Sort`，Rebuild 后使用 ST-Link 下载。需要 ARM Compiler 5 和 STM32F1 器件支持包（源工程为 Keil.STM32F1xx_DFP 2.2.0）。也可直接使用 `firmware/robot_arm_control.hex`。本次交付没有自动下载或驱动实机。
2. 上电后固件自动输出默认闭爪姿态 **[1500,1382,2157,1098,2191,1683]μs**，回位并等待。无需电脑 ARM 或心跳。上电前实物位置无法被固件获知，首次 PWM 仍可能产生回位动作。
3. FPGA 本地拨码 **1011** 进入 SORT，完成扫脸、回俯视与稳定后才有工件记录。非 ACTIVE 或无目标时的空心跳不启动抓取。
4. 首次映射，按 OLED 依次把**方块 3** 放在实际 **(10,10)、(20,10)、(15,20)、(5,20)、(25,20)cm**。这些点必须沿用原空间标定的原点、轴向和纸面刻度。每点先稳定约 1 秒，再连续记录至少 0.5 秒、至少 5 个有效包，并要求源帧推进。屏幕显示当前点、实时像素、目标信息、稳定进度与记录均值。
5. 每完成一点，移动方块3到下一实际点；旧点上的同一块标志不会自动录入第二步。全部五点采完后，使用五个像素均值与实际坐标共同做最小二乘仿射拟合，再按提示移走标定方块，连续确认已移走后开始正常观察。
6. 将工件静止放置。系统按空间位置关联目标，容许小范围像素抖动，等待整个场景和所有目标标签稳定。未知数字或标签仍在变化时，不冻结半批目标。
7. 确认后冻结最多四个目标，按实际 X 升序、X 相同时 Y 升序处理。圆形奇数 1/3/5 左放，圆形偶数 2/4 右放；方形3标定、不抓，方形1/2/4/5异常、不抓。过近、映射越界或超出原模型凸包的目标标记 `!`，不执行该点。
8. 抓取期间完全忽略新的视觉观测，包括目标丢失、数字变化和移动工件重识别。串口仍被持续消耗；不积压旧消息。整批完成、闭爪回默认并等待约1秒后，清空接收残片，重新开始观察。
9. 没有新目标进入空闲。已抓位置在重新观察后需确认消失约1秒才解除抑制，避免旧结果重复抓取。抓取过程中不要在同一原位置立即补入外观完全相同的新工件；视觉无法区分这种替换，需先让该位置被观察为空。

映射系数保存在 RAM，复位后重新进行五点映射。原有31点 PWM 模型是 const 数据，始终保存在 Flash 中，不会被五点映射覆盖。相机、桌面原点或机械臂安装改变时应重新映射并检查原空间标定是否仍适用。

## 单屏 OLED

固定 128×64、8 行 × 21 字符，无翻页、无轮播。为容纳四目标，采用清晰的紧凑英文缩写；具体布局和逐项中文释义见 [`docs/OLED与状态机.md`](docs/OLED与状态机.md)。

```text
PICK LOCK4 DONE0
#1 O2 C2 RIGHT
>1O2C2 10.0 15.0
-2S3C3 15.0 20.0
+3O3C1 20.0 15.0
-4S4C4 25.0 15.0
OPEN_HOME
RX IGNORED / LOCKED
```

`O` 圆、`S` 方；数字紧随形状；`C1` 等为 STM32 本地分类。`?` 未确认、`+` 已确认待抓、`>` 正抓、`*` 已完成、`-` 不抓、`!` 越界/过近等阻止动作。坐标为 cm。

## 动作与暂停

首次从默认闭爪开始：开爪 → CH2/3/4/6 到目标 → **CH5 最后下降** → 闭爪 → **CH5 先抬升** → 收臂 → 底座转左/右 → 伸出 → **CH5 最后下降** → 松爪 → **CH5 先抬升到原默认高度2191μs**。若批次还有待抓目标，保持爪子张开，直接调整CH2/3/4/6到下一目标上方，再调整CH5抓取；中间跳过默认回位及闭爪/重新开爪。最后一件放下并抬臂后，保持CH5高度，其他关节回默认的同时闭爪，完成后进入批末等待。跳过或被阻止的目标不算待抓目标。

每段继续使用零起止速度、零起止加速度的五次插值；各关节同步到段终点。限速作用于PWM指令，不代表实际末端直线或测量到位。暂停清除连续衔接许可并保留当前PWM。

2026-10-27按用户要求提高各关节速度、缩短段间停留并跳过无位移段；2026-10-28根据用户实物反馈将张开恢复为**1000μs**，闭合保持**1500μs**。连续化前，31个原标定点各左右抓放一次的62次指令时序模拟，平均由旧版30.62秒缩短为21.56秒（约29.57%）。这不包含识别确认/批末等待，也不是实机耗时。当前修改见[`docs/五点标定与夹爪更新_20261028.md`](docs/五点标定与夹爪更新_20261028.md)，前次提速参数与历史结果见[`docs/运动与夹爪优化_20261027.md`](docs/运动与夹爪优化_20261027.md)。

同日进一步提高关节限速并实现上述连续批次动作。当前496个四目标模拟批次平均从修改前86.25秒缩短为63.91秒，耗时减少25.90%；单目标62次模拟当前平均17.44秒。均为指令时序，不包含识别确认及批末等待。当前参数、删去的动作及验证见[`docs/连续抓放与再次提速_20261028.md`](docs/连续抓放与再次提速_20261028.md)。

暂停输入PB12拉低，立即冻结后续指令，保留当前PWM，不自动松爪、不自动回位。松开后保持暂停，按板上的RESET复位恢复；复位后重新执行五点映射。暂停状态下保留当前姿态优先于正常空闲默认姿态。重新开始映射同样使用RESET。

## 状态显示与 FPGA 现状

STM32的映射、确认、抓取、完成和方形异常信息在单屏OLED上显示，不上传电脑。与电脑连接的测试控制和事件输出代码、串口收发缓冲及监控脚本已移除。原FPGA到电脑的预览、状态和类别标签链路保持原状。

原 FPGA 板载 USB 接电脑继续用于预览和状态。`latest_plus_v3_fixed` 电脑/安卓软件已在上一轮同步为3.0.2，支持FPGA状态协议5；也可用FPGA本地拨码1011启用SORT。本轮在指定STM32工程内扩展五点映射，不修改FPGA或电脑/手机软件。完整目标数据仍走GPIOA6至PB11。

## 构建、参数与验证

- 编译：`python tools/build.py`，或 Keil Rebuild。可用环境变量 `KEIL_UV4` 指定 UV4.exe。脚本只编译，不烧录。
- 下载配置对照：`python tools/check_download.py`，对照原工程14组配置并检查六路PWM映射；构建脚本会在Keil自动升级项目字段后恢复原下载设置，再次核对。
- 离线检查：`python tools/check.py`，使用本机 GCC，假 PWM/事件回调，不连接串口。可用 `HOST_GCC` 指定编译器。
- 动作时序对比：先运行离线检查，再运行 `python tools/benchmark_motion.py`，覆盖原31点×左右两类，报告为 `tests/motion_comparison.json`。
- 连续批次对比：`python tools/benchmark_continuous.py`，覆盖31组位置×16种左右组合，共496个四目标批次，报告为 `tests/continuous_comparison.json`。
- 标定与基础姿态：[`docs/原标定参数记录.md`](docs/原标定参数记录.md)。原 `Calibration/model_data.h` 字节不变，标定 JSON 保存在 Reference。
- 视觉容差、确认时间、工作范围、OLED地址：`Vision/vision_config.h`；默认/左右姿态：`Protocol/pick_config.h`；轨迹限制：`Protocol/motion_profile.c`。
- 构建内存、HEX 摘要：`firmware/build_report.json`；离线结果：`tests/results.json`；测试覆盖与实机待验项：[`docs/验证记录.md`](docs/验证记录.md)。

原模型有交接包明确记录的局部空间误差（包括约10cm的一条验证记录）。本工程保留这些真实数据，没有通过修改记录掩盖误差。五点映射解决像素与纸面坐标的关系，不会消除原“纸面坐标→PWM”模型已有的机械落点误差。
